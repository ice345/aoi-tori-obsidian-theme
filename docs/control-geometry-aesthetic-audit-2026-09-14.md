# Aoi Tori 控件形状与整体美学审计

日期：2026-09-14。范围：当前工作区主题、上一轮已整合的 Callout，以及 Obsidian 原生 CSS 对主题的影响。本轮交付审计和修复方案；下文建议值尚未写入主题。

## 1. 结论与推荐方向

可以让按钮更圆润，而且值得做。当前普通文字按钮已有 8 px 圆角；明显的“方块感”主要来自图标按钮的 4
px 圆角、紧凑排列和工具组内部直角。把所有按钮统一改成圆形，会让带文字的操作、分段工具组和密集导航失去秩序。

推荐采用“柔和圆角作为主体，少量独立圆形作为节奏”的形状体系：文字按钮先试 10
px 圆角；普通工具栏图标采用 8–10 px；独立关闭、添加等单图标按钮，在确认布局后使用圆形；输入框保持 8
px。现有 Callout 的 22 px 图标、28
px 圆形底托继续保留。圆形底托是内容中的装饰容器，不应直接充当所有交互按钮的尺寸标准。

比形状更优先的修复是：深色移动端按钮的颜色覆盖、禁用输入控件的状态串扰。它们会影响阅读和操作判断。整体美学方面，优先调整形状、间距、阴影分工、状态节奏，避免通过降低文字透明度来制造空气感。

### 如何理解电影的空气感

官方访谈谈到透明的日常气息、细微变化的累积、纤细线条，以及如隔着玻璃观察的色彩感；声音也与学校空间和呼吸发生联系。这些可以转译为清楚但轻柔的层次、适量留白、克制的线条与微小反馈。[官方访谈](https://liz-bluebird.com/interview/)

官网页面的白色留白、浅蓝导航、粉色标题，与主视觉中的绿意及蓝色共同存在。因此，不宜把电影美学概括成“全部低饱和浅蓝”。深色主题更需要自行建立明度层级，而非把白天画面简单压暗。[电影官方网站](https://liz-bluebird.com/)

以下圆角、间距、阴影数值是 Aoi
Tori 的设计建议，官方资料没有规定按钮必须圆形。主题继续保持独立创作，不将电影图像、标志或角色素材加入发布包。

## 4. 逐项修复方案

### G01：图标按钮的圆角没有独立语义

**现状与原因。** `.clickable-icon` 直接使用 `--radius-s`，目前是 4 px。原生使用
`--clickable-icon-radius`；移动端原生变量已经变成 44 px，但主题仍输出 4
px。部分已定向适配的移动端按钮另有 8 px 规则，进一步造成不一致。普通图标夹具为 30 × 26
px，并非正方形，因此单独改成 `50%` 会得到椭圆。

**修复方向。** 在 primitives 定义形状值，在语义层映射
`--clickable-icon-radius`，组件消费这个官方变量。普通工具栏先试 8
px；独立单图标按钮在实际 DOM 中确认后，使用固定的方形视觉容器与圆角上限。需要触摸操作的区域继续维持至少 44
× 44 px 的项目目标，可让图标本身保持较小。

**实施要点。** 列出关闭、添加、面板操作、工具栏操作的真实选择器及父级布局；分别确认
`div.clickable-icon` 和 `button.clickable-icon`。不得全局对 SVG 设置宽高，不得给所有
`.clickable-icon` 强制 `aspect-ratio`，也不要将带文字的按钮裁成圆形。

**验收。**
静止、hover、active、focus 的外轮廓一致；焦点环不被父级裁切；关闭按钮不挤压标题；移动端圆角变量实际生效；带文字控件保持完整标签。

### G02：文字按钮与输入框共用 `--input-radius`

**现状与原因。** 普通按钮和输入框都消费 `--input-radius`，当前 8
px。若直接将此变量改为很大的值，会同时影响搜索框、设置输入框和选择控件。原生 `--button-radius`
已提供可区分的接口。

**修复方向。** 将按钮消费改为 `--button-radius`，保持输入框消费 `--input-radius`。建议首轮按钮 10
px、输入框 8 px；待长标签、密集设置页验收后，才考虑文字按钮 12
px。CTA 与警告按钮使用同一形状家族，通过语义色区分。

**验收。**
改按钮圆角不会改变输入框；短标签、长中文标签、图标加文字、窄窗口换行均不裁切；既有设置值仍可控制对应角色。

### G03：深色移动端悬停色串用边框强调色

**复现。** 在 `.theme-dark.is-mobile` 下，原生组合选择器定义：

```css
--interactive-normal: var(--background-modifier-border);
--interactive-hover: var(--background-modifier-border-hover);
```

当前主题使普通按钮静止背景成为 `rgb(70, 83, 95)`，悬停背景成为 `rgb(127, 195, 232)`，文字仍为
`rgb(229, 235, 235)`。后者的相对亮度对比约
**1.60:1**。这是启用的普通按钮，不属于禁用文字例外；普通大小文字以 4.5:1 为验收门槛。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

**影响边界。**
已复现 CSS 组合失败；不能据此声称所有手机触摸都显示 hover。平板外接鼠标、触控板及实际客户端的状态行为必须补测。

**修复方向。** 在移动端深色的匹配作用域中显式接回主题的按钮表面角色，使 `--interactive-hover`
使用深色可读的轻微提亮表面。按钮填充色与边框强调色拆开；不通过把全局边框强调色变暗来间接修补。同步检查移动端
`--background-modifier-hover`、form-field、overlay 等原生覆盖。

**实施位置。** 色值在 `semantic-dark.css` 的语义层定义；必要的平台覆盖在 `platform/mobile.css`
引用语义变量。先确认选择器权重，再决定最小组合；不使用 `!important`。

**验收。**
普通、CTA、警告按钮在深浅移动端的默认与 hover 文字均达到对应目标；按钮与图标各自仍有可辨识的状态变化；桌面不受回归影响。增加含原生 CSS 的回归场景，仅检查主题 token 本身不足以捕获此问题。

### G04：禁用输入控件的样式被后续基础及悬停规则覆盖

**现状与原因。** 禁用规则位于输入控件基础、hover 规则之前。`input[type="text"]` 与 `input:disabled`
存在同特异性覆盖；后面的 `input:hover`、`select:hover`
又加入边框强调和阴影。夹具中禁用文本框静止仍有输入阴影，hover 获得 2 px/8
px 阴影；禁用下拉框也从无阴影变成 hover 阴影。文本框最终 opacity 为原生的 0.5，未按主题预期统一成 0.68。

**修复方向。**
为启用态规则添加明确排除：`:not(:disabled):not([aria-disabled="true"])`；再让禁用状态在可预测的顺序和特异性下收束。区分 readonly 与 disabled，前者通常仍可聚焦、选择和复制。保留项目已有危险按钮组合保护。

**补充。** `button:active` 无条件位移 1
px；ARIA 禁用按钮的模拟 active 仍位移。对主题拥有的 pressed 装饰排除禁用状态。CSS 只能修视觉，`aria-disabled`
是否阻止事件由原生组件或插件代码负责，不能靠 `pointer-events: none`
冒充完整修复。原生 disabled 控件真实能否进入某伪类，要实机核验。

**验收。**
禁用控件不会因 hover 新增高亮或浮起反馈；正常按钮、输入框焦点环不消失；警告按钮仍保留禁用语义；readonly 可用行为不退化。不要把夹具里的不可真实触发状态误当事件漏洞。

### G05：通用选择器承担太多视觉职责

**现状。** `button, .mod-cta, .mod-warning` 同时承担表面、边框、阴影；另有广泛的
`input:hover`。实际插件可能使用 `button.clickable-icon`
或其他按钮式内部控件，导致图标按钮收到文字按钮的边框、阴影或按下位移。范围还可能包含未由同一基础规则覆盖的 input 类型。

**修复方向。**
拆分共同排版、文字按钮表面、图标按钮表面、危险操作状态；对输入框 hover 使用与基础样式一致的类型集合。先从真实存在的原生控件建立名单，避免为假设中的插件大面积重置。共享状态可采用低特异性组合，但必须与原生 CSS 一起验证最终优先级。

**验收。** 对 `button`/`div`
两种图标控件、range、checkbox、普通输入、选择器和 Canvas 实际元素进行回归。未知控件继续保持可用，不隐藏原生控件。

### G06：输入框和按钮的浮起感过于接近

**现状。** 两类控件使用相同 `--input-shadow` 与 `--input-shadow-hover`。当前普通阴影为 0/1/2
px，悬停为 0/2/7 px（浅色）或 0/2/8
px（深色）。这不属于功能错误，但在大量设置项排列时容易让页面显得由许多独立小卡片组成。

**修复方向。**
输入框以清楚的边界和内部表面为主，默认可尝试无外投影；普通按钮保留极轻阴影或仅用表面变化；图标按钮 hover 用淡色背景；浮层保留明确投影。为按钮与字段拆分阴影角色，避免修改一个 input
token 后误伤所有控件。

**验收。**
在 15 项以上的设置页观察整体层级；控件仍易定位，焦点强于 hover，hover 强于静止；菜单和模态框仍明显位于内容上方。保留可识别边界，不能把所有边框都降成近乎透明。

### G07：成组工具按钮需要整体圆角

**现状。** 原生 `.canvas-control-item` 使用直角，外层 `.canvas-control-group`
提供圆角与裁切。内部直边是连续工具组的结构，不应自动登记为缺陷。

**修复方向。** 优先尝试外层 10–12
px 圆角，保留内部接缝。若选择分离的圆形工具按钮，需要同时增加项目间距、移除不适用的共同边框并检查焦点裁切；这应作为独立布局变更，而不是一个全局 radius 补丁。

**验收。**
第一项、末项和单独一项都正确；纵向/横向排列成立；键盘焦点可见；缩放等标签不被挤压。实际 Canvas
DOM 未核对前，不把夹具标签当最终选择器依据。

### G08：密度与触摸尺寸缺少完整控件映射

**现状。** Compact/Relaxed 主要通过 `--input-height` 的 32/38 px 等变量影响控件；`.text-icon-button`
仍可能使用原生独立几何。夹具中文字图标按钮约 25 px 高，普通按钮默认 34
px。不同功能区可以有不同密度，但同一工具栏的垂直对齐和触摸面积应明确设计。

**修复方向。**
给文字按钮、工具栏图标、分组工具、移动端触摸区域分别定义几何角色；不要让所有控件共用一个高度。移动端已定向适配的区域继续保留 44
px 项目目标。密集桌面工具栏可以更紧凑，不能将夹具中小图标的尺寸直接判定为全部移动端的触摸缺陷。

**验收。**
在设置页、面板头、编辑工具栏和 Bases 工具栏分别检查三种密度；200% 缩放及长中文标签下无重叠；移动端真实点击区域不小于项目目标且互不覆盖。

### G09：Airy 的内边距顺序与名称不一致

**现状。** Callout 新默认是 `18px 20px`；Quiet 为 `8px 12px`；Airy 为
`16px 20px`。用户选择 Airy 后垂直留白反而减少。这是上一轮默认更新与既有设置之间的衔接问题。

**修复方向。** 保持用户已接受的默认预览效果，将 Airy 试调为
`22px 24px`，Quiet 保持紧凑，并验证小屏宽度。或者明确将“颜色浓淡”与“空间密度”拆成不同设置，避免一个名称同时控制不相关维度。先选一种方案，不同时增加多套复杂开关。

**验收。** 同一内容下 Quiet ≤ 默认 ≤ Airy 的留白关系成立；默认图标 22 px、圆形底托 28
px 不变；嵌套、折叠、无标题、长标题、窄屏无异常。颜色变化仍保持原有语义。

### G10：变量写了但未在实际层级生效

**现状。** `tokens/motion.css` 在 `:root` 设置 fast=120 ms，但原生 body 的同名变量使夹具最终获得 140
ms。排版的若干根级变量也受同类覆盖；字体迁移已在 PLANS 中作为延期工作记录，不是本轮新发现的已解决事项。

**修复方向。**
对确实由主题接管的变量，迁移至明暗模式或明确的 body 语义作用域；按变量逐项确认原生覆盖，不整体提高所有选择器权重。先让声明与结果一致，再决定是否保留 120
ms 或接受原生 140 ms。字体另设任务处理，避免圆角修复引发全库排版变化。

**验收。** 读取最终 computed
value；按钮与工具栏反馈节奏协调。现有无障碍模块明确关闭 reduced-motion 下的 transition/transform，本轮没有证据表明该保护失效，必须保留并复测。

### G11：逻辑边框与物理圆角不一致

**现状。** 引用、Callout 使用逻辑方向的起始边，但圆角是固定的
`0 r r 0`。RTL 下强调边移动，圆角仍保持 LTR 排列。

**修复方向。**
使用逻辑圆角属性，使起始侧两角与结束侧两角分别消费对应值；先确认原有直边属于视觉意图，再迁移。不要因调整方向破坏用户已接受的 Callout 样式。

**验收。**
LTR、RTL 的强调边与直边相邻；折叠图标、标题、正文和嵌套块均正确。此项目前为源级确定的不对称，客户端视觉仍待测。

### G12：空气感需要光学验收，不能只看变量

**检查点。** Quiet 状态栏使用整体 opacity
0.72；这会连同文字和图标一起合成。尚未逐背景测量，不应直接宣称对比失败。原创新 Callout 图标使用 1.25 的线宽，原生图标使用 1.8；复杂乐器与轻羽在 22
px 下的视觉重量也不能由数值直接判定。

**修复方向。**
状态栏优先使用可验证的语义前景色，减少整层透明度依赖。图标在 100%/125%/200% 缩放、深浅主题和不同像素密度下并排检查；只对过密路径或过弱局部进行光学校正，不全体加粗。圆形底托的色洗保持装饰角色，关键识别由图形和文字共同承担。

**验收。**
乐器轮廓互相可区分，细线不消失；状态信息可读；图标、文字、色洗不争抢注意力。无需为每个菜单、设置项新增电影意象图标。

## 5. 推荐形状体系与实现结构

| 控件角色                | 建议起点                          | 适用原则                                  |
| ----------------------- | --------------------------------- | ----------------------------------------- |
| 文字按钮、CTA、危险按钮 | 10 px 圆角                        | 标签完整，保持共同形状家族                |
| 输入框、下拉框          | 8 px 圆角                         | 稳定的书写容器，单独配置                  |
| 密集工具栏图标          | 8 px 圆角                         | 先保证排布，再评估 10 px                  |
| 独立单图标动作          | 方形容器、圆形轮廓                | 桌面试 28/32 px；触摸区域按移动端要求扩展 |
| 连续工具组              | 外层 10–12 px，内侧直边           | 保持连续关系与焦点可见                    |
| 菜单项目、导航行        | 4–8 px，按现有密度微调            | 无需每行胶囊化                            |
| 浮层、模态框            | 保留现有 8/12 px 层级，按实测调整 | 用空间和投影表达层次                      |
| Callout 图标底托        | 保留 28 px 圆形，图标 22 px       | 已接受的主题识别元素                      |

建议的文件职责：

1. `src/tokens/primitives.css`：新增必要的按钮、字段、图标形状基值；保留既有通用 radius，避免连带改变标签、表格等组件。
2. `src/tokens/semantic-light.css` / `semantic-dark.css`：映射
   `--button-radius`、`--input-radius`、`--clickable-icon-radius`，定义按钮与字段不同的表面及阴影角色。组件不新增颜色字面量。
3. `src/components/controls.css`：消费语义值，拆分角色，修正 disabled/hover/active 关系。
4. `src/platform/mobile.css`：以已验证的组合选择器修正平台覆盖和触摸区域；不覆盖未知组件几何。
5. `src/settings/style-settings.css`：同步密度与 Airy 的语义顺序；避免第一轮就新增多个形状开关。
6. `src/editor/content.css`：仅处理明确相关的 RTL 圆角；原有 Callout 样式继续保留。
7. `scripts/check-scenarios.mjs`
   及必要的原生组合检查：补平台优先级、禁用状态和实际角色尺寸断言；测试应检查可用行为结果，不只是重复 CSS 字符串。
8. 更新 DESIGN、TESTING、必要的 obsidian-dom 记录和 PLANS；通过 build 生成 `theme.css`。

## 6. 整体氛围：应该加强与应该保留的部分

色彩上继续以纸白、蓝灰、墨蓝承担大面积阅读空间，以柔和蓝、绿、紫等区分内容；粉色与较鲜明色只在合适角色点缀。错误、警告、删除操作保留可识别的语义色。深色模式优先保证背景、卡片、输入和悬停面各有足够明度差，不能重现用户最初指出的“框体消失”。

空间上，设置页和工具栏通过一致的间距形成呼吸；正文与侧栏保留不同密度。无需把全部容器做成大圆角卡片。树形导航、表格、代码块和元数据强调对齐与阅读，不宜强行圆形化。

交互上，让静止界面安静，hover 有轻微表面变化，focus 清楚，active 克制。避免每次指针经过都明显浮起、闪亮或位移。背景模糊、纸纹图像、全局透明效果均不是这轮的必要方案。

既有 Callout 的原创羽毛、双声部和乐器意象已经形成主题识别，优先打磨小尺寸一致性。无需为了“更像电影”扩大装饰数量。本轮也没有证据支持重做整套基础调色板。
