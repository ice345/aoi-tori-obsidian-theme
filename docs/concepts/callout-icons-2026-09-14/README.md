# Aoi Tori Callout 原创图标与美学方案

日期：2026-09-14。状态：设计提案，附可运行草案；尚未接入主题。

## 1. 结论

现有图标作为通用笔记图标是合格的，但主题专属的羽毛可以更有辨识度。推荐以「落羽」作为 Aoi
Tori 主图标，以长笛、双簧管组成可选的双声部，再提供大号、上低音号。保留普通音乐符号的通用用途，二重奏曲线作为更抽象的候选。

电影感应来自轻薄线条、偏心的形状、留白、相互回应的两个声部与克制的颜色。不要让每个 Callout 都成为乐器陈列，也不要仅靠增加图标或把颜色调淡来营造氛围。尤其不能削弱刚修复的暗色容器层次。

[打开交互比较页](index.html)：点击十五个候选，切换深浅色、18/22/24
px 使用尺寸以及圆形底托；下方同时展示 18/22/32/64
px 轮廓。页面是独立概念预览，不是实际 Obsidian 页面，示例类型不代表已经可用。

## 2. 现状与问题

实现位置：`src/editor/content.css` 的 `.callout-icon`、`.callout-icon svg`、`second-voice` 和
`aoi-tori` 类型规则。

| 现状                                 | 视觉影响                                           | 推荐方向                                                          |
| ------------------------------------ | -------------------------------------------------- | ----------------------------------------------------------------- |
| `aoi-tori` 使用 `lucide-feather`     | 均匀线条与规整封闭轮廓容易联想到羽毛笔、编辑按钮   | 使用弯曲羽轴、不对称羽片、少量断口的原创落羽                      |
| 25 px 圆形底托、18 px SVG            | 底托提供秩序，但同时把自然物变成徽章；羽毛显得拘束 | 专属艺术类型候选使用无底托的 22 px 图标；普通功能类型保持原有体系 |
| 全体 SVG 统一 `stroke-width: 1.8`    | 自定义细线与局部填充可能被统一笔画规则破坏         | 接入时为专属图标明确笔画规则，核对实际注入后的 SVG                |
| `second-voice` 使用 `lucide-music-2` | 音乐识别清晰，但无法表达两个声音之间的关系         | 保留通用音乐选项；另提供双曲线二重奏或具体乐器                    |
| 希望体现电影氛围                     | 单独更换一个物件不能自动建立完整美学               | 同时约束图标姿态、色彩、标题间距、视觉重心和出现频率              |

以上是设计判断。截图不能证明用户一定会把图标识别成某种物体，也不能证明所有显示设备的效果一致。

## 3. 怎样接近参考中的气质

参考图中羽毛具有方向性与重量变化：细长的羽轴、展开的羽片、偏向一侧的轮廓和浓淡差异。保留这些抽象特征，重新构造路径，不沿用参考图的外轮廓或羽枝排列。小尺寸无法承载真实水彩纹理，因此先保证剪影，再用有限的透明填充补充轻薄感。

官方访谈谈到纤细的线条、仿佛隔着玻璃的颜色、呼吸与细微动作。这些可以转译为 UI 的克制、空隙与轻微不对称，而不是添加复杂纹理。长笛与双簧管在作品中有明确的双人关系，适合作为主题的核心配对。[官方访谈](https://liz-bluebird.com/interview/)；[官方作品简介](https://ponycanyon.us/show/liz-and-the-blue-bird/)。

落地原则：

1. 羽毛略微倾斜、羽轴弯曲，两侧不镜像；只保留少数轮廓缺口。
2. 小尺寸以稳定线条为主，不模拟纸纹、颗粒、模糊与复杂渐变。
3. 蓝色与柔紫色分别服务两个声部，保留主题现有语义色；不是按乐器材质给铜管涂金色。
4. 两个声音共享尺寸与线条语言，但方向不同：长笛横向展开，双簧管纵向收束。这是本提案的视觉解读，不是官方人物配色或象征设定。
5. 主要靠静态间距与形态营造呼吸感，不添加持续漂浮、闪烁或粒子动画。

## 5. 推荐的使用层级

- `aoi-tori`：落羽。主题主符号，适合摘录、留存、轻量感想。
- `second-voice`：现有音乐符号仍可保留；二重奏作为更具主题性的替换候选，不强迫所有音乐笔记变成抽象符号。
- `flute`、`oboe`：可选的新类型。适合用户自行组织两个观点、两个角色或两组材料，不强制绑定人物性格。
- `tuba`、`euphonium`：扩展类型，按需使用；标题应写明乐器或笔记目的。
- 原生 `warning`、`error`、`success`、`bug` 等：保留清楚的功能符号与语义颜色。普通 `quote`
  不统一替换为羽毛。

上述新类型名称是提议。正式实现前需检查现有别名及插件冲突，并在 README 给出示例；必要时使用
`aoi-flute` 等前缀。

## 6. 接入实现方案

### 6.1 图标与绘制规格

统一 `viewBox="0 0 24 24"`，当前草案基本笔画为 1.25 单位、圆端点和圆连接，继承 `currentColor`。在 22
px 输出时笔画约为 1.15 CSS
px；这是候选值，不是已验证的所有设备最优值。建议在实际 Obsidian 中比较 1.25 与略粗的 1.4，暗色模式优先保证轮廓清楚。

落羽的透明填充是辅助，不能把可辨识性建立在低透明色块上。长笛的细小键位与铜管的多重回旋需要逐个光学校正；统一画布不等于感知大小一致。若实际使用只有 18
px，应另做删减键位的简化版，不直接缩小全部细节。

### 6.2 原生接入路径

Obsidian 支持通过 `--callout-icon`
提供 SVG 元素字符串，无须为此引入图标插件。[官方 Callout 文档源](https://github.com/obsidianmd/obsidian-help/blob/master/en/Editing%20and%20formatting/Callouts.md)。

后续实施顺序：

1. 确定落羽主版本，将原创 SVG 转为 CSS 中合法的单行 SVG 字符串；保留可编辑的 SVG 源文件。
2. 在 `src/editor/content.css` 内针对具体自定义类型设置
   `--callout-icon`；优先使用原生变量，避免改变未知内部结构。
3. 将当前全体 SVG 的 1.8 笔画与 18 px 规则改为可由专属图标覆盖的配置。检查真实 DOM，确认根 SVG 的
   `fill`、`stroke`、大小及子路径属性没有被原生处理覆盖。
4. 仅对这一组专属类型尝试无圆形底托、22
   px 图标。保持标题对齐、合理点击范围与原生折叠箭头；图标装饰尺寸不应成为折叠操作的命中区域上限。
5. 图标颜色沿用现有 Callout 语义变量。新增尺寸或笔画基础值遵循 primitives → semantic →
   component 结构；不把预览页调色板复制进组件规则。
6. 新增类型逐项声明图标与语义色，防止嵌套时意外继承父 Callout 的乐器图标。
7. 不改变已经修复的 `normal` 混合模式、容器表面与边界；新图标不是背景可见性的修复替代品。
8. 从 `src/` 构建 `theme.css`；更新设计文档、使用说明与必要的场景检查。

无需远程字体、远程图片、Base64、滤镜纹理或新依赖。独立预览页的 JavaScript 仅用于比较，不进入主题发布内容。

## 8. 第二轮：小号、低音铜管辨识与六种新意象

### 8.1 大号和上低音号为什么必须重画

用户指出的问题成立。首轮主要改变了同一个 U 形的宽度，在统一画布和缩略尺寸下差异会被抵消。第二轮采用不同结构的代表形制：

- **大号**：宽圆腹与大喇叭口、横列转阀，视觉重心更低、更横向。
- **上低音号**：修长的椭圆回管、高而窄的喇叭口、三枚朝上的活塞，视觉重心更纵向。
- **小号**：横向吹嘴与管路、三枚活塞、向右张开的喇叭口，和长笛形成清楚的外轮廓区别。

比较页新增独立的「同尺寸比较」，让大号与上低音号在 18/22/32/64
px 并排展示，避免依赖放大图判断。仍不承诺在 18 px 下可以无文字辨认乐器；本轮首先修复同形缩放的问题。

大号存在活塞式和转阀式，选择转阀大号是为了在这组图标里获得可读的结构差异，不是说只有大号使用转阀、只有上低音号使用活塞。草案省略部分管路和阀件，不是精确型号示意。[Yamaha 大号形制](https://www.yamaha.com/en/musical_instrument_guide/tuba/mechanism/)；[Yamaha 转阀大号结构](https://www.yamaha.com/en/musical_instrument_guide/tuba/mechanism/mechanism002.html)。小号根据吹嘴、活塞、回管及喇叭口重新绘制，没有复制厂商图形。[Yamaha 小号结构](https://www.yamaha.com/en/musical_instrument_guide/trumpet/mechanism/)。

### 8.2 从资料到图形，而不是把所有物件都收进来

重新查看官网页面，可以看到白色页面、浅蓝导航与粉色标题；当前主视觉里的森林与花卉又有更丰富的绿和暖色。因此不能把作品概括成「所有东西低饱和、全部淡蓝」。主题应保留大面积中性空间与少量清晰色彩，区分现实空间的透明感和童话画面的丰富度。[电影官网](https://liz-bluebird.com/)。

访谈提及隔着玻璃观察、细线的脆弱感、小变化的积累，以及学校物件参与声音制作。本提案据此选择窗、换气、脚步与余响。它们是设计转译，不是导演指定的图标语义。[山田尚子官方访谈](https://liz-bluebird.com/interview/)。

官网公开的原声曲目也包含风、玻璃、脚步、图书馆与回声等意象；这支持从日常声音及空间寻找设计方向，但曲目名称不能作为某个具体镜头或剧情象征的证明。[官网音乐资料](https://liz-bluebird.com/)。

所有新图标均为 24 × 24 的原创向量路径。大号和上低音号覆盖原有草案文件；其余六个旧候选保留。

### 8.4 推荐取舍与色调

最推荐优先使用：**落羽、长笛、双簧管、微开的窗、换气、童话书页**。它们兼顾主题关联与笔记用途。青鸟具有很强的标志性，建议少量使用；余响与脚步适合作为用户按需选择的扩展。小号和两种低音铜管组成乐器选项，不必成为全部笔记的默认符号。

配色继续使用既有纸白、冷雾、蓝和柔紫角色。本轮没有另加一套自称「官方准确色值」的调色板；官网图片随画面变化，不存在可直接等同于 UI 语义角色的统一取色结果。

- 亮色中的空气感：靠纸白与留白托住蓝色线条，不把图标本身淡到看不清。
- 暗色中的空气感：保留清楚的轮廓和独立容器层次，让空隙存在于图形内部及图文之间。
- 绿色、粉色和暖色不按图标数量不断增加；否则整组会从双声部变成彩虹分类。
- 细小图标不堆水彩纹理、星光或装饰光晕；不通过降低整组 opacity 获得所谓透明感。
- 原有安全语义、折叠控制与主题专属装饰图标仍分开处理。
